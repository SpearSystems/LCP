LCP Ack Message

https://lcp.dev/schemas/ack.json · Response to any message. Uses errors[] array — a single message can fail multiple field validations. Created by Spear Systems (a Spear company). Open standard — Apache 2.0, free to implement.

Top-level properties

PropertyTypePII classRequiredDescription
dispositionallOfrestrictedv1.3 (LEP-0012 §1): the commercial result of the acknowledged lead or post. A lead is sold if, and only if, outcome = sold. Sent only when the acknowledged message's lcp.version is 1.3.0 or later, and only on an ack whose status is RECEIVED, ACCEPTED or DUPLICATE; a DUPLICATE ack repeats the original disposition. Classed restricted because redirect_url is session-bearing.
errorsarrayinternalZero or more error objects. Present when status = ERROR or REJECTED.
lead_idstringinternalAssigned lead ID, if applicable.
negotiationobjectinternalLEP-0009 §5: the negotiation outcome carried on every ack for a quote/counter (and on the bid ack of a successful redemption), so a buyer never infers state from prose. Absent on a v1.1 exchange.
original_message_idstringinternalyesID of the message being acknowledged.
rejection_reasonstringinternalStructured reason the lead was refused or not bought: with status = REJECTED, or (v1.3, LEP-0012) with disposition.outcome = unsold or price_rejected. Known values: invalid_phone, invalid_email, duplicate, out_of_geography, out_of_scope, credit_too_low, already_customer, data_quality_fail, compliance_fail, price_too_high, capacity_exceeded, consent_expired, litigator_flagged, no_buyer. Open enumeration.
request_idstringinternalServer-side request ID for tracing.
